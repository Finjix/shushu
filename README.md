# Shushu

Finjix 的终端风格静态个人主页，展示“技术 × 设计”的个人介绍和两段实习经历。使用原生 HTML、CSS 和 JavaScript，无构建步骤或运行时依赖。

## 浏览方式

- 启动页中间是 macOS 风格的终端图标（`终端.app`，下方呼吸提示“点击开始”）；点击图标或页面任意位置，终端窗口从图标处展开，随即输入 `cat welcome.html` 并播放个人介绍，配有键盘音效。点击启动图标、打开任意预览（图片、视频、试玩）以及图片/视频揭晓时，统一使用同一声短促的“叮”。
- 图片和视频按板块预加载：进入某个板块时立即加载它自己的资源，同时在后台预取下一个板块、再往后一个板块排在最后，首屏不会一次性加载全部资源。详见下方“预加载”。
- 介绍及第一段实习结束后显示继续提示：桌面端为“↓鼠标滚轮或单击继续”，向下滚动，或点击结尾提示符 `finjix@AI-Native ~ %` 所在行及其下方区域进入下一段；移动端或窄屏为“单击继续”，轻点提示符所在行及其下方区域进入下一段。点击提示符上方的正文和配图区域不会继续。
- 也可使用 Enter 或空格继续。播放期间和重复操作不会重复开启内容；向上滚动仅用于回看，点击实习图片只打开预览，不进入下一段。
- 依次输入 `cat 实习经历01.html` 和 `cat 实习经历02.html`，显示网易互娱和点点互动 AI Foundry 的实习经历；随后是 `cat showcase.html` 作品展示、`cat flowx.bin`（CASE X：FlowX AI 应用平台，右侧为 16:9 平台演示视频）、`cat 精选案例01.html`（营销素材 AI 生产管线，右侧为操作演示视频与同批弹窗、内容流成品）、`cat 精选案例02.html`（视频 AI 混剪，含流程图与成片）、`cat 精选案例03.html`（AI 3D 试玩广告，内嵌可直接操作的试玩）、`cat 精选案例04.html`（定制 Agent 与需求智能体），最后是 `cat about_me.md`（ABOUT ME：头像、姓名、届别与所在地（状态两项一行）与联系方式、技能标签和自嘲）。旧内容保留在上方，新命令行保持可见，结尾提示符紧接正文。最后一段结束后不再显示继续提示；ABOUT ME 结束后也不再显示末尾的提示符。
- 点击左上角圆点打开设置与跳转菜单，可直接跳转到个人介绍、任一实习经历、作品展示、任一精选案例或 ABOUT ME，也可切换动画效果与终端启动页。关闭动画后文字立即显示，动画和音效停用。设置保存在当前站点的浏览器 `localStorage` 中，刷新后仍然保留：动画开关立即生效，终端启动页开关在刷新后生效。浏览器禁止存储时，切换仍对当前页面有效。

## 板块左右对齐规范

- **桌面端所有双栏板块的实际可见内容必须上下对齐**：右侧媒体顶部对齐左侧内容起点（有副标题时从副标题开始），右侧最后一项内容的底部对齐左侧最后一段正文的底部。不能只让外层容器等高，也不能用空白占位假装对齐。
- **可读性优先于底部对齐**：为对齐而等比缩小正文时最低只缩到 0.9 倍（`main.js` 中的 `MIN_CASE_TEXT_SCALE`）。到下限仍对不齐时（正文远长于配图，或屏幕较窄），保持顶部对齐，资源位占满右栏，底部不再强求对齐。
- 桌面端内容区宽度为 `max(62.5vw, min(100vw - 96px, 880px))`、水平居中：宽屏（≥1408px）仍是左侧 3/16 留白、5/8 内容宽；平板、小笔记本和手机横屏放宽到最多 880px，避免双栏挤压正文。
- 图片、视频保持原始比例；右侧图片与其下说明的左右边缘也要对齐，不单独缩成居中小图。更换内容、调整窗口宽度或浏览器缩放后仍需重新校准。
- **正文段距固定，不得用 `space-between` 拉大段距凑高度**。CASE 04 的段间距与副标题下方间距均为 24px；右栏保持 42% 宽，图片满宽显示。右栏只放配图。按完整正文（含下方三项说明）预先测量两侧高度，调整右栏宽度使图片底部与左侧三项说明底部对齐；右栏到一半宽仍矮于正文时等比缩小正文（不低于 0.9 倍；到下限仍高于配图时右栏回到 42%，只对齐顶部），打字期间不反复改变布局。
- 精选案例三项要点：奇数案例（CASE 01、03）用横排指标 `.case-stats`（三栏、每项上方横线），偶数案例（CASE 02、04）用竖排编号列表 `.case-features`；CASE X 保持竖排。CASE 04 的三项要点放在左侧正文下方。
- CASE 01 - 营销素材 AI 生产管线右栏为拼图资源位（`.case-mosaic`）：16:9 演示视频与 2:3 竖版弹窗按 8:3 分栏等高并排，690×188 内容流图通栏在下；桌面端间距取拼图宽度的 2.5%，整体宽高比固定，脚本把整块拼图当作一个横版资源位计算列宽（上限 52%，不足时等比缩小正文，不低于 0.9 倍），使视频/弹窗顶部对齐副标题、通栏图底部对齐左侧三项指标底部。拼图内各项比例互锁，揭晓时不单独缩小。上述双栏对齐要求仅适用于桌面布局，≤700px 时仍按正文、媒体纵向排列。
- 布局变更需验证完整内容和动画结束后的效果，检查实际元素边界（误差不超过 1px），不能只检查容器尺寸。浏览器回归覆盖 CASE 04 与 CASE 01 - 营销素材 AI 生产管线的 800、1024、1280、1751、1920、2560px 宽度及移动端回退：未到缩放下限时上下边都对齐，到下限时顶部对齐、配图底部不超出正文。窗口拖拽缩放时列宽在停止缩放约 150ms 后重算，板块首次显示时立即计算。

## 移动端布局

屏宽 ≤700px 时使用独立的一套布局（`styles.css` 末尾的移动端区块）：内容占满屏宽（两侧 20px，含安全区），不再沿用桌面端的左侧留白和 5/8 宽度；公司 logo 单独一行，放在公司名下方、岗位上方；图片一行一张，实习02 的横竖两段视频等高并排，精选案例的两段 9:16 媒体平分一行，试玩预览按屏高限宽。手机上揭晓媒体时不再按可用高度缩小，自动滚动直接跟到媒体和结尾的「单击继续」提示（命令行此时早已滚出视口）。桌面端揭晓时按可用高度缩小的媒体，在窗口尺寸变化或旋转后恢复自然尺寸。

## 本地预览

运行中的预览服务会在修改 `public/` 后约 1–2 秒内自动更新：

- **仅修改 CSS**：原地替换样式，不刷新页面，当前板块、滚动位置和已打开的预览保持不变。
- **修改 HTML、JavaScript 或资源**：保存当前板块、已展开内容和滚动锚点后重新加载，直接恢复当前位置，不回到启动页、不重播打字动画；正在播放的段落会直接补全。媒体弹窗和试玩内部状态不恢复。
- 状态仅用于本次自动更新，按标签页隔离，不修改设置或依赖 `localStorage`；手动刷新仍保持原来的启动行为。试玩 iframe 不注入更新脚本。

修改普通页面文件无需重启服务。预览服务支持视频 HTTP Range 分段请求，拖动进度条时可直接读取目标片段，不必先下载完整视频。若从旧版预览服务升级到本版（包括视频分段支持），请先在原服务窗口按 `Ctrl+C`，再运行 `start.cmd`（仅此次需要重启；仅刷新网页不能升级运行中的 Python 服务）。

首次启动可双击根目录的 `start.cmd`，或在仓库根目录运行 `python scripts/dev-server.py`，然后访问 `http://127.0.0.1:8000/`。`start.cmd` 自动打开浏览器：已有本项目预览服务时直接复用，端口被其他服务占用时安全报错，不会结束任何已有进程。也可运行 `python scripts/dev-server.py --open-browser`。新服务启动后保持命令窗口打开，按 `Ctrl+C` 停止服务。更新脚本 `scripts/dev-client.js` 仅由本地服务注入，不会进入线上页面。

动画模式由站点开关控制，不随系统“减少动态效果”设置变化。即使 JavaScript 不可用，个人介绍、实习图片和带原生控件的视频仍会直接显示，设置菜单禁用。

页面支持浏览器缩放；图片预览内使用独立的滚轮/双指缩放。媒体弹窗保留左上角装饰圆点栏，不设置独立关闭按钮或扩大点击区；点击内容外的背景区域或按 Escape 可关闭。视频弹窗复用内联视频元素，打开后取消静音并从头播放；底部仅保留进度条，不显示时间或文字按钮；画面中央使用播放/暂停图标（暂停时常显，播放时鼠标悬停不显示，仅键盘聚焦时显示）。点击画面、中央图标或聚焦画面后按空格/Enter 可暂停或继续；拖动进度条时临时暂停，松开后恢复拖动前的播放/暂停状态，进度更新不会抢回滑块位置，拖动也不会误触画面或关闭弹窗；关闭后恢复静音内联循环播放。试玩弹窗不显示视频控件。

## 内容与验证

正文及命令文案位于 `public/index.html`，布局位于 `public/styles.css`，播放流程、输入方式和设置持久化位于 `public/main.js`。命令中的文件名仅用于终端展示，不会请求独立的 HTML 或 TXT 文件。修改脚本或样式后，同步更新 HTML 中资源链接的版本参数，避免旧缓存。

提交前运行：

```sh
node --check public/main.js
node --test tests/convert-images.test.cjs
python -m unittest discover -s tests -v
git diff --check
```

图片转换测试使用 Node.js 和系统 FFmpeg，覆盖有损质量 100 编码、归档冲突与动画保护；Python 测试仅使用标准库，覆盖资产检查、预览注入、视频分段响应和端口复用。可选浏览器回归测试不参与构建或部署：

```sh
npm install --no-save --package-lock=false playwright-core
npx playwright-core install chromium
node tests/browser-smoke.cjs
node tests/dev-reload.cjs
```

`dev-reload.cjs` 自动启动临时预览服务，在隔离的页面副本上验证 CSS 热更新、HTML/JS 更新后的板块与滚动恢复、手动刷新行为，不修改工作区文件。`browser-smoke.cjs` 测试前确保预览服务已运行；`PREVIEW_URL` 可指定测试地址，`BROWSER_EXECUTABLE` 可指定本机 Chrome/Edge，`PLAYWRIGHT_MODULE` 可指定外部安装的 playwright-core 路径。测试覆盖桌面/320px、无脚本媒体、菜单滚轮、预览关闭、视频弹窗、动画切换/取消及存储受限回退。视频测试直接使用真实服务（不模拟分段响应），同时验证滑块、实际播放时间与解码画面的中点位置一致。仍需手动验证真实移动设备的点击、滑动回看及双指缩放。

## 预加载

板块内容由 `cat` 手动触发，下一个板块可预知，`main.js` 里的预加载队列按此安排：

- 板块内所有带 `data-src` 的 `<img>` / `<video>` 都由队列加载；新增图片、视频时用 `data-src`，并写上实际的 `width`/`height`，加载完成后原位出现、不挤动布局。没有脚本时的显示放在 `<noscript>` 里。
- 原图远大于内联显示尺寸时，`data-src` 指向展示尺寸版本（`<原名>-<宽>x<高>.webp`，宽约 1280px，覆盖 2x 屏），`data-full` 指向原图；`width`/`height` 仍写原图尺寸。图片预览先显示已解码的内联图，原图下载并解码后再替换。`<noscript>` 回退的 `<img>` 用展示版本，外层链接仍指向原图。
- 每个内联视频用 `data-poster` 写首帧封面（`<原名>-poster-<宽>x<高>.webp`），队列开始加载该视频时才设置，不在页面打开时请求；`<noscript>` 回退视频直接写 `poster`。
- 优先级：当前板块（立即加载、不限并发、图片 `fetchpriority=high`）> 下一板块（后台预取，最多 2 个并发）> 再往后一个板块及跳转时上方的旧板块（只在前两者都下载完后才开始）。
- 视频预取只拉元数据和首帧（`preload="metadata"`），轮到当前板块时升级为 `auto` 继续缓冲。名额在图片下载完、视频拿到首帧/元数据、出错或 8 秒超时后释放。
- 省流量模式（`Save-Data`）或 2G 网络下只加载当前板块。
- 播放到某段时最多等待 5 秒资源；超过 300 毫秒仍未就绪时在正文下方显示 `Loading...`。从菜单跳转只等待目标板块最多 1.5 秒，上方旧板块的资源在后台补齐。
- 内联视频离开视口时暂停，回到视口时继续；揭晓（包括菜单跳转一次性揭晓上方板块）时位于屏幕外的视频不播放，滚入视口后才开始。试玩 iframe 不进队列，另有调度（见上方精选案例03）。

## 图片资产

所有新增或替换的位图必须使用**有损 WebP（质量 100）**。先将图片放入 `public/asset/` 对应目录，再运行：

```sh
node scripts/convert-images.cjs
```

需安装 Node.js 和系统级 FFmpeg（含 libwebp 编码器），并确保 `node`、`ffmpeg`、`ffprobe` 在 PATH 中；图片转换不依赖 Python 或 npm 包。脚本使用 FFmpeg 的 `libwebp` 编码器，以 `-lossless 0 -quality 100` 进行有损编码，并验证尺寸、可解码性和透明通道（RGB 像素允许变化；质量 100 不等于无损），更新 HTML/CSS/JS/JSON 中的完整资源路径引用，将原图归档到根目录 `original-assets/`（保留 `public/asset/` 内相对目录结构），然后移除 public 内原图。同名 WebP 或归档已存在时会拒绝覆盖；替换资产请使用新文件名。相对路径或动态拼接引用需手动更新。动画图片需单独转换并验证；SVG 保持矢量格式。

展示尺寸版本与视频封面同样走上述流程：用 FFmpeg 从 `original-assets/` 中的原图（或部署视频的首帧）缩放出 `<原名>-<宽>x<高>.png`（封面为 `<原名>-poster-<宽>x<高>.png`）放入 `public/asset/` 对应目录，再运行转换脚本；中间 PNG 作为该 WebP 的原图归档，原图与已有 WebP 不变。缩放使用 `scale=<宽>:<高>:flags=lanczos+accurate_rnd+full_chroma_int`，带透明通道的图片（如 Century Games logo、营销弹窗）在缩放前后加 `premultiply=inplace=1` / `unpremultiply=inplace=1`，避免边缘发黑。

视频不参与 WebP 转换：直接放入 `public/asset/` 对应目录，用原生 `<video>` 引用（`data-src` 交给预加载队列），原片同时保留在 `original-assets/`。当前 UE 玩法视频使用 VP9 WebM（CRF 32、原始分辨率 1080×960、30 fps、Opus 64 kbps），原始 MP4 保留在归档中；CASE X 平台演示直接使用原始 H.264/AAC MP4（1920×1080、30 fps，15.92 MiB），部署文件为 `public/asset/casex/platform-demo.mp4`，与归档 `original-assets/casex/platform-demo.mp4` 字节一致，不再重复转码；此前 VP9 CRF 32 版本反而达到 23.78 MiB，已移除。相同内容在 Git 中共享同一个 blob，归档与部署副本不会重复存储。营销素材管线操作演示由 GIF（1040×585、420 帧，17.17 MiB）转为 VP9 WebM（CRF 32、原始分辨率、按 15 fps 重排时间戳保留全部 420 帧、无音轨，1.54 MiB），部署文件为 `public/asset/case01/marketing-multi-size-ab-skill-vp9-1040x585.webm`，原 GIF 归档在 `original-assets/case01/`。其他 VP9 视频播放需目标浏览器支持，当前未提供 H.264 回退。

精选案例02 正文右侧（`#case02-videos`，窄屏时移到列表下方）并排放置 9:16 的流程图和成片 03（`public/asset/case02/成片03-vp9-720x1280.webm`：原片 1440×2560、60 fps H.264 MP4 转为 VP9 WebM，CRF 32、缩放到 720×1280、保留 60 fps 全部 1800 帧、Opus 96 kbps，6.43 MiB；原片归档为 `original-assets/case02/成片03.mp4`）。新增成片时：把转码后的视频放进 `public/asset/case02/`（原片同时归档到 `original-assets/case02/`），按 `index.html` 中 `#case02-videos` 内注释的模板添加带 `data-src` 的 `<video>`，并同步在 `<noscript>` 内添加对应的回退视频。`width`/`height` 写视频的实际尺寸；弹窗比例按视频实际宽高自动计算，多个视频并排时按同一高度缩放以适配屏幕。

ABOUT ME（`#about-section`）类似 neofetch：左侧头像（`public/asset/about/avatar.webp`，616×616，原图归档在 `original-assets/about/`），右侧依次为姓名、状态（2027 届、所在地等，每行两项）、邮箱和电话（纯文本）；移动端头像与姓名、状态并排，联系方式另起一行。该板块不使用额外动态效果：带 `data-reveal` 的块（头像、技能标签）预先占位，穿插在正文中，打字进行到其后第一段文字前像其他配图一样自上而下逐行揭晓；姓名、状态与联系方式各行也预留高度，逐行打出时已出现的内容不移动。增删技能直接编辑 `.about-skill-list` 中的 `<li class="about-skill">`；自嘲（SELF-ROAST）目前为占位文字。

精选案例03 用 `<iframe data-src>` 内嵌 `public/asset/case03/围炉煮冰-试玩.html`（Three.js 单文件试玩，模型、贴图和脚本以 zip 形式内嵌在 HTML 中）。两处 iframe 都带 `sandbox="allow-scripts"`（不同源），支持的浏览器（如桌面 Chrome）会把试玩放到独立进程，试玩启动时约 1 秒的主线程占用不再卡住本页的打字动画和滚动。内联 iframe 只作自动演示预览（不响应操作，`?preview` 半帧率），在该段揭晓后、浏览器空闲且出现在视口内时才加载，不参与下一模块预取；离开视口或弹窗打开时暂停渲染，段落被重置时卸载。点击后在 macOS 风格的媒体弹窗中从头加载一份完整帧率的试玩（窄屏全屏），展开动画结束后才开始加载，关闭后内联预览直接恢复、无需重载。试玩页没有声音（原先的合成 BGM 已移除），内置一个 `requestAnimationFrame` 闸门，响应父页面的 `postMessage({ playable: 'pause' | 'resume' })`，并把试玩内的 Escape 转发给父页面关闭弹窗。原始试玩保留在 `original-assets/case03/`；部署版本关闭了 Bloom 炫光（bundle 中 `bloom` 默认改为关闭，URL 加 `?bloom=1` 可恢复对比），去掉了 three.js 启动时上百条 `toNonIndexed` 警告，内嵌的 PNG/JPEG（包括封面与警示语 data URI）已按项目规范转为有损 WebP（质量 100，透明通道与尺寸已校验，内嵌文件名不变，加载器按文件头识别格式）。

部署版本还修改了 bundle（`web/main.bundle.js`）中的玩法与动画：
- 冰熊与猛犸会转身：主角（其次是守着它的猎人）进入识别范围（离身体冰熊 6.5、猛犸 7）时朝目标转身，进入攻击范围（冰熊 4.5、猛犸 5）才出手；转身先加速后减速（最快冰熊 0.9、猛犸 0.7 rad/s），可转到任意方向（原来只能在初始朝向 ±20° 内偏头），转身时冰熊保持雕塑姿态、整个身体随步子左右摇摆起伏并略向转向一侧倾斜，猛犸对角两腿一组交替前后迈步、身体轻晃，碰撞与挨打用的身体按模型实测轮廓重新定义在模型自身坐标里、绕模型转身的支点一起旋转（原来冰熊的碰撞体与可见身体错开约 1 m、猛犸的与身体垂直，主角会走进模型里）；挨打时不再按 22 Hz 来回抖，改为一次轻微后坐再缓回。
- 冰熊与猛犸会反击：主角（或守在怪前的猎人）在近旁且怪物已转向目标时，怪物先蓄力（地面红色预警区由近到远填满，冰熊为扇形、猛犸为圆形；身体抬起后撤），随后扑击/踩踏，落地出现冲击环和冰屑；主角此时在预警区内会被击退约 1 m 并后仰（击退后约 0.3 s 内不响应移动输入），猎人只做受击后仰；蓄力早期目标离开则收势取消。
- 自动演示的目标选择加了“做完再换”：钱箱有钱就收到空、手里有钱就把钱花完，原来钱箱每进一笔就掉头，主角在钱箱和地块之间来回抽动，跟随主角的镜头随之抖动。
- 东门与东北门朝背离主角的一侧推开（按主角进入门口区域时所在的一侧判断，原来只朝营地外开，从外面回来时门扇往主角身上开），并在 0.22 s 内平滑推开、离开后 0.35 s 关上（原来一帧弹开、分级跳着关）。
- 猛犸象鼻不再插进雪地（原来静止时就低于雪面约 0.3，扑击后更深）：每帧按需把象鼻下段向前卷起，最低处保持在雪面 0.15 以上；踩踏时象鼻先随身体扬起、落地后在恢复阶段慢慢垂下。
- 去掉了围绕主角、指向下一个目标的黄色箭头（目标上方的跳动箭头保留，主角到达目标后也不再消失）；加载封面（ 背景，内嵌 360×780 截图）按当前版本首屏重新截取，转为有损 WebP（质量 100）。
- 渲染时间在最近两个 1/120 s 模拟步之间插值，高刷新率屏幕或帧间隔不均时镜头和角色不再一顿一顿。
- 排队顾客：队伍前移时从当前实际位置继续走（原来会瞬移回上一格或一步跳过 2.8 m），每一步开始时按剩余距离规划步幅，中途接到新位置不再让双腿突然换姿势；被服务后在约 0.15 s 内转身跑开（原来一帧内转 135°）；排队站立时身体是约 0.7 Hz 的缓慢摆动（原来是 6 Hz 的快速抖动）。猎人到位后在 0.3 s 内转向怪物。
